## Abstract

This publication's applied-systems series has so far asked whether a stated fact could be trusted without being computed (paper one), whether a claimed action could be trusted without being checked against an execution record (paper two), and whether a reported reliability number disclosed what kind of evidence actually stood behind it (paper three). A shorter field note in this same line, examining A.R.C.H.O.N.'s closed tool manifest, left an explicit question open: closed-world grounding is straightforward for a small, fixed tool registry, but what happens when the claim at stake is not which tool to call, but whether the system is capable of a specific outcome it has never been independently verified on? This paper is the fourth entry in the series and the direct answer to that open question — found not as a thought experiment, but as a dated, real incident inside this publication's own geometry-prediction subsystem, NIER.

The intuitive answer is that a model should learn to express its own uncertainty honestly — hedge when it doesn't know, commit when it does — and a harness downstream should simply read that signal off. The incident this paper documents shows that answer is not available, not because the model lies, but because it has nothing honest to report: when the subject model was wrong, it was wrong with the same confidence, and the same complete absence of internal disagreement with itself, that it showed when it was right. A model with no internal signal of its own error cannot be asked to disclose one. What this paper documents instead is a fix that never asks it to: a capability claim gated not by what the model believes about itself, but by an external, independently maintained record of what that specific class of claim has actually been right about before — computed the same way this publication's first paper insisted a fact should be, and trusted for the same reason.

*A system that has never been shown it is wrong is not confident. It has simply never had the chance to disagree with itself.*

## Section 1 — The Problem, Named by the Field

Tool-augmented agents are, as of late 2026, still measurably bad at knowing the edges of their own competence, and the field's own benchmarks now say so in specific numbers rather than general complaint. A three-level diagnostic benchmark splitting tool use into judgment, planning, and execution stages, run across twenty-nine mainstream models, found that even the best-performing model reached only 42.79 percent on a composite reliability score built to be sensitive to exactly this kind of partial failure — not a measure of whether a model can complete a task once, but of whether its tool use holds together end to end (*Agent-Trident: A Three-Level Progressive Diagnostic Benchmark for Tool-Use Hallucination in LLM Agents*, Findings of ACL: EMNLP 2026). The gap is not closing with scale. A separate measurement study recorded 322 genuine tool hallucinations across ten hosted models and two invocation surfaces, and found that a 675-billion-parameter model matched a model roughly a hundredth its size on the rate at which it fabricated calls to tools that were never real (*Closed-World Resolution Against Tool Hallucination in LLM Agents*, arXiv:2609.19425, Sept. 2026). The same study makes the architectural point this publication's own closed tool manifest was independently built around: a hallucinated call is, by construction, not a decision any downstream gate made, so no downstream gate — however well designed — can be the thing that catches it. The defense has to sit earlier than the gate, at the point where a name resolves to a real instrument or doesn't.

That architectural fix — a closed, re-validated registry — answers the question of which tools exist. It does not answer a harder, adjacent question this publication's own prior field note left explicitly open: what happens when the registry is correct, the tool genuinely exists, and the model is asked to use it on something it has never been shown before — and the failure is not calling a tool that isn't there, but confidently misjudging what the real tool actually produced? That failure mode has its own name in 2026's literature, and its own measured mechanism. A causal-intervention study accepted to NeurIPS 2026 treats "confidently wrong" as a literal, locatable property of a model rather than a figure of speech: large language models, the authors find, routinely assign high confidence to incorrect predictions, and existing calibration methods — post-hoc adjustment, retraining — operate only on the output, never on why the miscalibration happens in the first place (*Why Are LLMs Confidently Wrong? Correcting Overconfident Errors via Causal Head Intervention*, NeurIPS 2026, arXiv:2610.34994). Their own fix, intervening directly on the internal attention and MLP circuits responsible, is real and measured — Expected Calibration Error fell by as much as 36.6 percent on one model/benchmark pair (Mistral-7B on MedMCQA, 0.0604 to 0.0383) — but the gains are uneven across models and benchmarks, several sit inside the model's own reported standard deviation, and accuracy drops slightly in more than one case. This is the field's best current answer to repairing a model's confidence from the inside, and it is expensive, partial, and model-specific even when it works.

A companion mechanistic study explains why the inside is a hard place to fix from. Verbalized confidence inflation, it finds, is not noise — it is written by a compact, identifiable set of attention heads and MLP blocks concentrated in a model's middle-to-late layers, consistently, at the final token position, regardless of whether the answer behind that confidence is correct (*Wired for Overconfidence: A Mechanistic Perspective on Inflated Verbalized Confidence in LLMs*, arXiv:2604.01457). A model does not drift into overconfidence by accident. It has a circuit for it, running on every output, whether or not that output deserves the confidence the circuit assigns.

Read together, these four findings describe one coherent shape: the field has confirmed that tool-use reliability is a real, quantified, stage-by-stage problem (Agent-Trident); that the fix for one layer of it — hallucinated tool identity — has to run structurally earlier than any gate (Closed-World Resolution); that the harder layer above it — a model confidently misjudging a real tool's real output — is a located, mechanistic property of the model, not a reporting failure (Why Are LLMs Confidently Wrong?); and that the mechanism producing it is a genuine internal circuit, not a symptom with no cause (Wired for Overconfidence). What the field has not yet connected is what this paper connects directly: if overconfidence is a circuit that fires the same way whether the model is right or wrong, then no amount of asking the model to be honest about its own confidence — however it is prompted, trained, or post-hoc adjusted — can be the mechanism a production system actually relies on. The incident in Section 2 is this publication's own, direct, dated confirmation of exactly that, inside a system small enough to inspect completely.

## Section 2 — What This Looks Like From the Inside

NIER is this system's live intent- and geometry-prediction subsystem — a small transformer that, among other duties, takes a plain-language description of a physical part and predicts which of eight real AXF primitive kinds (box, tube, cylinder, shell, housing, gear, lattice, plate) the description refers to, plus the continuous parameters that kind needs. Its synthetic held-out test — drawn from the same generator that produced its training data — scored 100 percent kind accuracy on the 2026-10-17 checkpoint. That number was true and worthless in the same breath: it measured whether the model had memorized the generator's own templates, not whether it understood the shapes those templates described.

The real test, built specifically because the synthetic one could not be trusted to catch this, is twelve hand-written descriptions, phrased the way an actual person talks, never run through the template generator that produced the training data. The same checkpoint that scored 100 percent on the synthetic split got six of those twelve wrong. Some of the misses were not close calls: "a thin rectangular slab" — unambiguously a plate — scored box at 98.4 percent confidence. "A sealed container with rounded edges on every corner" — a housing by any ordinary reading — scored box at 98.1 percent. For comparison, "a hollow dome, like half a ball" scored shell at 99.3 percent and was correct. Nothing in the confidence number distinguished the two confidently-wrong cases from the confidently-right one; all three sat in the high nineties.

Before concluding the model was simply poorly calibrated — a known, generic failure mode with known, generic partial fixes — the check that was actually run was harder to fool than reading a softmax number: thirty stochastic forward passes with dropout kept active at inference time (Monte Carlo dropout), a standard technique for surfacing a model's own internal disagreement with itself across repeated samples. On every one of the confidently-wrong cases, all thirty passes agreed with each other, on the wrong answer, every time. This is the detail that rules out the comfortable explanation. A model that is secretly unsure but reporting false confidence would disagree with itself across repeated stochastic samples; this one did not. It had not failed to notice its own uncertainty. It had none to notice. It had learned a specific, wrong, and — by the only internal measure available — completely stable association between certain real-world phrasing and the wrong shape.

Both findings were logged the same day, against the same checkpoint, as part of the same session: the model could not be asked to disclose what it did not have, and the two standard techniques for eliciting exactly that disclosure — a confidence score and a stochastic-disagreement probe — both returned clean, stable, wrong answers with no caveat attached.

## Section 3 — Why the Obvious Fix Doesn't Work

The obvious next move, and the one most teams reach for, is calibration aimed at the model itself: retrain with a confidence-penalizing loss, apply temperature scaling, or — per Section 1 — intervene directly on the internal circuits responsible, the way the NeurIPS 2026 causal-head-intervention study does. Each of these is a real, legitimate technique, and none of them would have been the wrong thing to try. But Section 2's MC-dropout finding rules out the premise all three share: that there is a recoverable internal signal, obscured by some correctable distortion, waiting to be uncovered by a better internal probe or a better internal nudge. There was no disagreement to recover. Thirty independent stochastic passes converged, every time, on the same wrong answer — which means the thing a calibration technique would be calibrating is not noise sitting on top of a real signal. It is the model's actual, confidently-held, wrong belief, expressed as cleanly as its correct ones.

This is a sharper version of the limitation Section 1's own cited fix ran into without naming it this way: *Why Are LLMs Confidently Wrong?* reports real, measured ECE improvements from its causal head intervention, and those improvements are genuine — but they are also uneven, partial, benchmark-specific, and occasionally purchased at a small cost to accuracy, on exactly the kind of multiple-choice task where a correct answer is well-defined and the space of wrong answers is small and enumerable. NIER's task — free-form geometric description, eight classes, open-ended real-world phrasing — is a harder target for the same kind of intervention, and this paper's own incident gives a specific, concrete reason why "calibrate the model better" was not pursued as the fix here: there is no evidence, in this system, that a better-calibrated version of this model's confidence signal is achievable at a cost smaller than what the field's own best current technique cannot yet promise cleanly even in its easiest setting.

The conclusion this forces is not that calibration research is wrong — Section 1's citations are real, serious, measured work, and nothing here contradicts them. The conclusion is narrower and more specific to what a production system can actually rely on today: a fix that depends on successfully reading an honest signal out of the model's own cognition is a fix that depends on that signal existing to be read, and this paper's own incident is a direct, dated case where it did not. A gate built on that assumption would have gated nothing; it would have asked a model with no doubt to report one, and received, instead, the same clean confidence it always gives.

## Section 4 — The Pattern: Gate on the Record, Not the Report

The fix that was actually built does not ask NIER anything about itself. It asks a question NIER has no part in answering: of the times this specific predicted class has been checked against real, independently-graded ground truth before, how often was it right?

The mechanism has three real pieces, each one deliberately kept separate from the model it evaluates. First, a generalization eval — the twelve hand-written, never-templated descriptions from Section 2 — is run after every retrain, specifically because the synthetic held-out split cannot be trusted to measure anything but template memorization. Second, the eval's results are aggregated per predicted class, not overall: a model that is reliable on "shell" and unreliable on "box" does not average out to "somewhat reliable" — each class gets its own real correct/total count, with a minimum-sample floor (two) below which the status is reported honestly as "insufficient data" rather than guessed at in either direction. Third, and the step that actually closes the loop: that per-class record is loaded, at inference time, by the exact same code path that serves every live prediction, and attached to the prediction as a "reliability" field the caller cannot strip out or ignore by omission — a predicted class with a real track record of being wrong carries a written warning that says so explicitly, in the same response, regardless of how confident the model's own softmax number looks sitting next to it.

This is the same discipline this publication's third paper described one level up, now pushed one level further down. That paper's finding was that two honest numbers, sitting at the same visual weight, can carry categorically different statistical authority if one isn't labeled as to its kind — and the fix was to say, at the point of reading, what kind of evidence a number rested on. This paper's fix applies that same principle to a single number's trustworthiness rather than to two numbers' comparability: a confidence score is not accepted as self-certifying just because it is large. It is checked against the one thing that can actually certify it — a real, dated, independently-scored track record — and if that record says the class is unreliable, the system says so in the same breath as the prediction, every time, regardless of what the model itself would have claimed if asked.

Nothing about this requires NIER to become more honest, more self-aware, or better calibrated. The model can go on being exactly as confidently wrong about "box" as it was on 2026-10-17; the claim that reaches whoever is reading the prediction is no longer the model's claim alone. It is the model's claim, stamped with an external, structurally separate record of how often that specific claim has actually held up before — grounded the same way this publication's first paper insisted a fact should be grounded: computed from real data the generative process did not produce and cannot edit, not generated by the same process being checked.

## Section 5 — Evidence: Real, Dated, and Inspectable at the Level That Matters

This publication's prior papers in this series drew a consistent boundary: the general shape of a fix is disclosed in full; the private system it was built inside is not opened for direct inspection, and that limit is stated rather than implied otherwise. This paper holds the same boundary, with one difference worth naming plainly: the specific numbers in Section 2 are not a hypothetical restated for publication. They are the literal contents of this system's own checkpoint-evaluation artifacts, dated 2026-10-17, produced by running the real eval script against the real checkpoint — not a summary written after the fact from memory of what happened.

Before the fix: a live prediction for a description like "a thin rectangular slab" returned a kind, a confidence number, and nothing else — 98.4 percent, box, full stop. A caller with no access to the generalization eval's own output — which was not surfaced anywhere in the live prediction path before this fix — had no way to know that this exact class of prediction had a real, measured history of being wrong on language shaped just like this.

After the fix: the identical request returns the same kind and the same confidence number — the underlying model is untouched — plus a third field that did not exist before: a reliability record stating, in the clearest case, "real warning: 'box' was wrong on 6 of 6 real (non-templated) test descriptions — the confidence number above does not reflect this; treat this prediction as unverified regardless of how confident it looks." For a class with a clean record, the same field instead states plainly how many real test descriptions that class has been right on. For a class with fewer than two real test cases on record, it says exactly that — insufficient data — rather than defaulting to either an implied pass or an implied warning.

What changed is not the model's competence. The model is exactly as likely to mispredict "box" today as it was on 2026-10-17; nothing in this fix retrains, fine-tunes, or recalibrates it. What changed is whether a claim the model cannot verify is allowed to reach a decision-maker unaccompanied by the one piece of context that actually bears on whether it should be trusted — and that piece of context comes from outside the model, every time, by construction.

## Section 6 — Discussion and Limitations

This fix closes a narrower gap than its title might suggest, and the gap it leaves open is worth naming precisely rather than letting the word "grounding" imply more than was built. What exists today is a system structurally incapable of letting an unreliable capability claim reach a reader *unflagged*. It is not yet a system structurally incapable of *acting* on that claim regardless of the flag. The reliability field this paper describes is diagnostic, by explicit design and explicit code comment: it is attached to every live prediction, but nothing downstream is yet wired to refuse, block, or escalate a prediction on the basis of its own "unreliable" status the way Anubis's invariant gate blocks a proposed state change on the basis of a violated rule. Closing that second gap — making the warning load-bearing, not just visible — is real, named, unstarted work, not a detail being glossed over.

A second limitation is one this paper's own evidence should have caught applying to itself, and did, on a second look: the reliability note attached to each prediction states a real count — "wrong on 6 of 6" — without stating what *kind* of six that is. All twelve generalization-eval cases are a fixed, hand-written battery, built to catch drift across retrains, not a random sample of the descriptions this system will actually receive in production. That is exactly the distinction this publication's third paper drew between a Wilson-bounded estimate and a fixed regression battery sitting at the same visual weight — and it has recurred here, at a different site in the same codebase, in a field built after that paper's fix was already shipped elsewhere in this system. The honest conclusion is not that this new field repeats the old mistake in its effect — a sample size of six is disclosed, which the pre-fix state did not even offer — but that it has not yet finished applying the label-the-kind-of-number discipline to itself. That is this paper's own open item, not a neighboring one.

Third, the minimum-sample floor of two is a deliberately low bar, chosen because the real alternative at this corpus size is reporting nothing at all rather than reporting too little — and "insufficient data," honestly labeled, is a better default than a confident-sounding number with two observations behind it. It is still a real blind spot: a class can sit at "insufficient data" for a long time at this scale, during which a caller gets no warning and no clean bill of health, only an honest shrug. That is the correct behavior for what is actually known. It is not the same as safety.

Last, this paper answers the capability-calibration half of the question this publication's own field note left open; it does not answer the half that note named explicitly as the harder one — whether closed-world grounding holds as a tool registry grows and tools begin composing with each other. NIER's eight classes are a small, fixed, hand-curated set. Nothing in this paper's evidence speaks to whether per-class track-record calibration remains tractable, or remains honest, at a hundred classes instead of eight, or when classes themselves start overlapping the way this publication's own research notes already documented happening on NIER's separate intent-classification side. That is real, open, and explicitly deferred — not a gap discovered here, but one this paper does not claim to have closed.

## Section 7 — Conclusion

The question this paper set out to answer was whether an agentic system can be made structurally incapable of claiming a capability it doesn't have. The honest answer, supported by a real, dated, inspectable incident rather than an argument from first principles, is: yes for the claim reaching a reader unflagged, not yet for the claim being acted on regardless. The mechanism that produced that yes is not the one the intuitive version of the question assumes. It does not require the model to know what it doesn't know, to hedge honestly, or to disagree with itself when it's wrong — Section 2 showed directly that this specific model does none of those things, cleanly and repeatably, and Section 3 showed why asking it to is not a tractable fix with the field's own best current tools. What works instead is colder and cheaper: an external record of a specific claim's own real history, computed independently of the claim-making process, attached to every instance of that claim whether or not the model making it has any idea its own track record exists.

This is the fourth entry in what remains an ongoing line of work, not a closed one. Section 6 named the next real boundaries plainly: making the reliability flag load-bearing rather than advisory, finishing the label-the-kind-of-number discipline on the reliability field's own sample count, and testing whether any of this holds once the registry this pattern runs on stops being eight hand-curated classes. Those are not loose ends set aside for tidiness. They are, as with the three papers before this one, the actual agenda for what gets built and written about next.

## Availability

This publication's prior papers in this series described a fix's general shape while keeping the specific system it was built inside closed to direct inspection, and stated that boundary rather than implying otherwise. This paper holds the same boundary on the system as a whole. It differs in one respect worth stating plainly rather than letting the distinction blur: the numbers and code comments quoted in Sections 2 and 5 are reproduced verbatim from this system's own dated evaluation artifacts and inference code, not paraphrased from memory after the fact — a narrower but more directly checkable form of evidence than this publication has offered in its first three papers, for this one specific incident. What is not disclosed is the surrounding system this incident occurred in, beyond what the sections above describe.
